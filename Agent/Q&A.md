##### 1.Agent反复重试直到耗尽迭代预算，在生产环境中，设计怎样的检测和终止机制？
###### 问题描述
![[截屏2026-10-15 19.44.49.png]]

###### 解决
三层终止机制：
```
第一层：硬限制
限制最大轮数、Token、执行时间和预算。

第二层：重复行为检测
对工具名和规范化参数计算指纹，判断是否重复执行相同操作，并结合结果判断是否有进展。

第三层：无进展检测
观察任务状态是否变化，而不是只统计工具调用次数。
```

**对工具名和规范化参数计算指纹**：把一次工具调用（工具名 + 规范化参数），类似于一次操作的md5码，防止重复调用工具。不用原始参数是因为调用参数顺序不同，空格、大小写、格式不同，浮点数精度。可以规范化参数，json参数拼成稳定的字符串，算哈希值等。

当任务流程明确、容错率低、需要严格审计时，受限动作空间通常更合适。

##### 5. 人工干预机制要求 Agent 能“优雅地移交控制”。但在实践中，用户可能不在线、响应很慢、或者给出模糊的指令。此时 Agent 应该怎么办？

Agent 可以等待、暂停和保存状态，但不能因为用户没有回复就默认获得高风险操作的授权。
- 超时机制：等待一定时间后暂停，而不是无限阻塞。
- 状态持久化：保存任务进度、工具结果和待审批操作。
- 安全默认值：高风险操作未获明确批准就不执行。
- 异步通知：通过邮件、消息等方式提醒用户。
- 恢复机制：用户回来后，从暂停点继续执行。
- 审批有效期：恢复时重新检查环境、参数和资源状态。
```
Agent 准备执行生产部署，用户两小时后才批准。此时必须重新检查代码版本、部署目标和环境状态，不能无条件执行两小时前的计划。
```

### 巡检原理

巡检的配置在ops-api的命名空间，前端通过调用 ops-api 的接口获取巡检项列

#### 方式一：构造全量包
```
  **完整验证流程图**

  1. 提交配置文件到 git，修改配置文件：
     参考刘震分支修改：
     [http://code.sangfor.org/ADS/DSP/Platform/dsp-integration/tree/feature-inspect-lz](http://code.sangfor.org/ADS/DSP/Platform/dsp-integration/tree/feature-inspect-lz)
     
     ↓
  2. 构建 bin 包并升级集群
     ↓
  3. configmap ops-api-config 中包含 inspect-items-override-zh-CN.yaml
     ↓
  4. ops-api 启动时加载配置，重启生效
     ↓
  5. 前端通过 API 调用 ops-api 获取巡检项列表：
     GET /api/ops/inspect/v1/items
     ↓
  6. 前端导航菜单中的"系统巡检"链接触发
     ↓
  7. 前端渲染巡检项树形结构，显示"底座巡检 > 日志链路 > DSP日志是否严重堆积"
     ↓
  8. 用户点击执行，创建巡检任务（必须重新创建巡检任务才可以生效）
     ↓
  9. ops-api 执行 VM 插件查询 Pulsar 堆积数据
     ↓
  10. 根据 result_failure_expr 判断是否超过 10000 条
     ↓
  11. 渲染结果模板并返回前端显示

```

#### 方式二：直接修改configMap（推荐）

#### 为什么前端能自动看到新的巡检项
  
  1. 巡检配置文件==（inspect-items-zh-CN.yaml）==作为 configmap 挂载到 ops-api pod

  2. ops-api 加载配置时解析 YAML，构建巡检项树

  3. 前端每次请求 /api/ops/inspect/v1/items 都会获取最新的树结构

  4. 前端导航菜单中的"系统巡检"页面是通用的，不需要单独配置

### 查看巡检配置

##### **查看** **configmap** **中的配置文件列表**

这会显示 configmap 中包含的所有文件

yaml格式
```
kubectl -n operations get configmaps ops-api-config -o yaml
```
文本格式
```
kubectl -n operations describe configmap ops-api-config
```

或者导出到本地查看

```
kubectl -n operations get configmap ops-api-config -o yaml > /root/wjx/dsp-integration/ops-api-config.yaml
```

这就是会显示所有configMap的配置yaml文件以及对应的文件内容

筛选指定的yaml文件，查看配置

```
kubectl -n operations get configmap ops-api-config -o jsonpath='{.data.inspect-items-override-zh-CN\.yaml}'
```

### 增加新的巡检任务

##### 导出 ConfigMap
方式一：本地编辑

```bash
kubectl -n operations get configmap ops-api-config -o yaml > /root/wjx/dsp-integration/ops-api-config.yaml
```

方式二：在线编辑

```
kubectl -n operations edit configmap ops-api-config
```

![[截屏2026-03-20 15.59.28.png|500]]
注意缩进整齐
```
- name: "DSP_LOG_BACKLOG"  
  description: "DSP日志是否严重堆积"  
  scenarios: ["BUSINESS", "FULL"]  plugin_type: "vm"  plugin_config:    query: 'sum(pulsar_subscription_back_log{topic=~"persistent://10001001/default/http_log|persistent://10001001/default/dsp_http_log.*"})'    duration: "5m"    step: "60"    result_failure_expr: "{{gt .value 10000}}"    failure_level: "warn"    result_format: "string"    success_template: "日志堆积正常，当前堆积量: {{.value}} 条"  
    failure_template: "日志严重堆积，当前堆积量: {{.value}} 条，超过阈值 10000 条，请检查富化服务和入库服务是否正常"
```


##### 应用新的configmap配置
方式一：
```
kubectl -n operations apply -f ops-api-config-latest.yaml
```
方式二：
直接保存即可
##### 重启pod

```
kubectl -n operations rollout restart deployment ops-api
```

检查重启状态：

```
kubectl -n operations rollout status deployment ops-api --timeout=120s
```

##### 验证新的配置是否生效

```bash
kubectl -n operations get configmap ops-api-config -o jsonpath='{.data.inspect-items-zh-CN\.yaml}' | grep -A15 "DSP_LOG_BACKLOG"
```

##### 后台查询PromQL指标

打开一个终端A：

```bash
kubectl -n monitor-platform port-forward svc/vmselect-vmcluster 18481:8481 &
```

打开终端B：

查询堆积量
```bash
curl -s -G 'http://localhost:18481/select/0/prometheus/api/v1/query' \
  --data-urlencode 'query=sum(pulsar_subscription_back_log{topic=~"persistent://10001001/default/http_log|persistent://10001001/default/dsp_http_log.*"})' \
  | python3 -m json.tool
```

预期返回：

```
  {
      "status": "success",          // 查询成功
      "data": {
          "resultType": "vector",   // 即时向量（当前时刻的值）
          "result": [
              {
                  "metric": {},     // sum 聚合后没有标签
                  "value": [
                      1773991671,   // Unix 时间戳（2026-03-20 15:27:51）
                      "0"           // 当前堆积量：0 条
                  ]
              }
          ]
      },

      "stats": {
          "seriesFetched": "2"      // 匹配到 2 个 topic 的时间序列
      }
```



#  文件解析整体流程

## 流程说明

文件解析流程是将各类非结构化文件转换为可供模型推理使用的标准化数据的关键环节。该流程通过压缩包检测与解压、文件类型识别、专用解析器处理、OCR 文字提取、两级文本清洗五个阶段，最终产出一份 JSON 文件和一份 Markdown 文件传递给下游。

## 触发条件

上游任务调度模块在采样决策通过后，将待解析文件送入本模块。

## 输入

各类非结构化文件：doc、docx、pdf、xlsx、pptx、txt、json、csv、html、xml、jpg、png、bmp、tiff、zip、rar、7z、tar、gz 等。

## 主要步骤

### 第一步：压缩包检测

系统拿到文件后，首先判断该文件是否为压缩包（zip、rar、7z、tar、gz 等）。如果是压缩包，则进入压缩包解析器进行解压，解压后得到内部文件。对于每个内部文件，重新回到本流程的起点，依次判断是否为压缩包、识别类型、送入对应解析器。压缩包嵌套深度最大为 5 层。

如果不是压缩包，则进入下一步文件类型识别。

### 第二步：文件类型识别

通过读取文件头部字节（Magic Number / 魔数）来判断文件的真实格式。例如：PDF 头部为 % PDF，Office 文档头部为 PK（ZIP 格式），各类图片各有独立魔数。

对于无固定魔数的纯文本类文件（txt、json、csv、html、xml 等），通过文件后缀名进行兜底判断。

总结：**文件类型识别策略 = Magic 头优先 + 后缀名兜底**。

### 第三步：解析器路由

文件类型确认后，根据类型将文件送入对应的专用解析器：

- **PDF 解析器**：处理 .pdf 文件，提取文本内容，同时提取文件中嵌入的图片。
- **Office 解析器**：处理 .docx、.xlsx、.pptx 等 Office 文档，提取文本内容及嵌入图片。
- **图片解析器**：处理 .jpg、.png、.bmp、.tiff 等图片文件，直接进行 OCR 文字识别。
- **纯文本解析器**：处理 .txt、.json、.csv、.html、.xml 等文本文件，进行编码检测后直接读取内容。

每种文件类型对应一个专用解析器，后续新增支持或修改逻辑只需维护对应解析器，互不影响。

### 第四步：OCR 图片文字提取

解析过程中默认开启 OCR。解析器在处理文件时提取其中嵌入的或独立的图片，对图片进行 OCR 文字识别，抽取出图片中的文字内容。

### 第五步：组装原始解析结果

解析完成后，将文件文本内容和图片 OCR 结果拼装成统一格式：

【文件名称】：xxx

【文件内容】：xxx

【图片 1 文字】：xxx

【图片 1 描述】：xxx

【图片 2 文字】：xxx

【图片 2 描述】：xxx

...

每张图片包含两个字段：OCR 识别出的文字内容，以及图片本身的描述信息。

### 第六步：两级文本清洗

所有解析器输出的原始结果都要经过文本清洗模块。清洗采用两级机制：

#### 公共清洗规则（所有文件类型都走）：

十条规则覆盖：去除 Markdown 标记（##、**、- 等）、去除 HTML 标签、过滤页眉页脚（页码、版权声明等）、中文标点统一（英文标点转中文标点）、去除竖线 | 替换为中文分号、合并被不当拆分的短行、保持地址完整性、手机号标准化为 11 位纯数字、统一空格、首尾清理去多余空格和空行。

#### 专用清洗规则（按文件类型分别配置）：

针对不同文件类型的特殊格式，配置该类文件专属的清洗规则。例如 PDF 解析结果可能有特定的格式残留、Office 文档可能有特定的排版标记等，各自走自己的专用清洗逻辑。这样避免所有文件类型都走过一遍不必要的清洗步骤，减少性能开销，也更便于维护。

### 第七步：输出

最终输出两份文件：

- **JSON 文件**：12 字段标准结构化数据，包含文件 ID、文件名、文件类型、MIME 类型、文件大小、MD5、规范化纯文本等。
- **Markdown 文件**：原始解析结果的 Markdown 格式版本，保留文档结构信息。

## 输出 / 下游

最终产出的 JSON 和 Markdown 文件传递给下游的模型推理模块，由模型提取内容进行分类分级推理。模型推理部分不在本模块职责范围内。

# Q&A
### 判断文件类型

专门弄一个列表，文件头匹配到字段就是这个文件类型，写代码直接if判断

### 文件内容清洗模块

专门维护一个很长的列表，去遍历清洗或者针对文件类型去清洗，会有公共清洗，之后根据文件类系去专门的格式去清洗

### 为什么转化为pdf

因为代码无法进行版面解析，会解析出来文字，但是排版是混乱的，上一句接不到下一句，会造成语意的混乱，影响到模型理解，虽然速度很快，但是效果不好

版面解析就是转化成图片，这个速度较快，一个脚本，之后去ocr，效果很好。

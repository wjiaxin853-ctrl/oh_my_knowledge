### MLP（多层感知机）

MLP 由多个**层**组成，每层都是**全连接**的

**比喻**：想象一个传送带工厂——输入层是原料入口，隐藏层是多道加工车间（每道车间都用所有原料加工），输出层是成品出口。隐藏层越多，加工越复杂，能处理越“难啃”的问题。

MLP 使用**监督学习**训练，主要靠**反向传播算法**

### Embeding（向量化）

| 步骤    | 叫什么          | 作用                       | 输出是什么        | 举例（以“我爱北京”为例）                        |
| ----- | ------------ | ------------------------ | ------------ | ------------------------------------ |
| 分词/切分 | Tokenization | 把文本切成模型能处理的小单元           | token（整数 id） | ["我", "爱", "北京"] → [100, 234, 5678]  |
| 向量化   | Embedding    | 把每个 token id 转成一个高维有语义向量 | 向量（一串浮点数）    | 100 → [0.12, -0.45, 0.89, ..., 0.03] |

##### 1.输入原始文本：

**我爱北京天安门**

##### 2.Tokenizer（分词器）

把文本切分成tocken，输出一个tocken id，序列，

**[100, 234, 5678, 1234, 890]**

##### 3.Embedding 层（模型的第一层）
把每个 token id 转换成向量，输出：一个矩阵，**每行是一个 token 的 embedding 向量**

形状通常是：[序列长度, 隐藏维度]，比如 [5, 4096]

- ==**Token** = 登机牌上的座位号（只是一个编号：12A、35C）==
- ==**Embedding** = 乘客本人（带着身高、体重、长相、性格等所有信息） 登机牌（token id）只是用来找到这个人（embedding 向量），真正上飞机被处理的，是这个“活生生”的向量表示。==

###### Tocken Embeding，input Embeding，Position Embeding区别

| 名称                     | 中文常用叫法         | 作用（一句话）                                  | 输入是什么            | 输出是什么                    | 是否包含位置信息  | 是否可学习  | 维度通常是                     | 在 Transformer 中的位置   |
| ---------------------- | -------------- | ---------------------------------------- | ---------------- | ------------------------ | --------- | ------ | ------------------------- | -------------------- |
| **Token Embedding**    | Token 嵌入 / 词嵌入 | ==把每个 token变成有语义的向量==                    | Token ID（整数）     | 稠密向量（dense vector）       | **不包含**   | 是（可训练） | [batch, seq_len, d_model] | 第一步                  |
| **Input Embedding**    | 输入嵌入           | Token Embedding + Position Embedding 的总和 | Token ID + 位置    | ==最终送入 Transformer 的向量== | **包含**    | 部分可训练  | 同上                        | 真正喂给 Attention 的输入   |
| **Position Embedding** | 位置嵌入           | ==告诉模型当前 token 在句子中的位置顺序==               | 位置序号（0,1,2,3...） | 同样维度的位置向量                | **只包含位置** | 有两种实现  | 同上                        | 加到 Token Embedding 上 |
![[截屏2026-01-11 17.26.03.png|200]]

```
原始文本 → Tokenizer → Token IDs 序列
                             ↓
                   Token Embedding 层
                             ↓           ← 每个 token 独立查表，得到语义向量（没有位置感）
                   + Position Embedding
                             ↓           ← 把位置信息编码加进去
                   = Input Embedding   ← 这才是真正送进 Transformer 第一层的向量！
                             ↓
               Self-Attention + FeedForward...
```

### Shape（形状）

**shape（形状）** 指的是张量（Tensor）的**维度结构和尺寸**

```
# 0维张量（标量）: shape = ()
scalar = torch.tensor(5)          # shape: torch.Size([]) 或 ()

# 1维张量（向量）: shape = (n,)
vector = torch.tensor([1, 2, 3])  # shape: torch.Size([3]) 或 (3,)

# 2维张量（矩阵）: shape = (m, n)
matrix = torch.tensor([[1, 2], 
                       [3, 4]])   # shape: torch.Size([2, 2]) 或 (2, 2)

# 3维张量: shape = (b, m, n)
tensor_3d = torch.randn(2, 3, 4)  # shape: (2, 3, 4)

# 4维张量（图像批量）: shape = (b, c, h, w)
batch_images = torch.randn(32, 3, 224, 224)  # shape: (32, 3, 224, 224)
```

###### reshape（重塑）

```
# 将4D张量展平为2D（用于全连接层）
# (batch, channels, height, width) -> (batch, channels*height*width)
x = torch.randn(32, 3, 28, 28)  # shape: (32, 3, 28, 28)
x_flat = x.view(32, -1)         # shape: (32, 2352)   # 3*28*28=2352
# 或
x_flat = x.reshape(32, -1)
```

### 基础模型

==基础模型 = 没有经过指令微调的“原始野兽”，==它只经过了**预训练（Pretraining）**阶段。

- 训练目标：**海量无标注文本 + 下一个词预测（Next Token Prediction）**。
- 结果：模型学会了语言的语法、语义、世界知识、基本模式，但**不会“听指令”**。

### Instruction Tuning（指令微调）

==Instruct/Chat 版 = 被人类好好调教过的“乖巧助手”==

**Llama 3 8B Instruct 中的 “Instruct” 意思是：**这个模型是经过 “指令微调”（Instruction Tuning） 的版本，专门被训练成“听懂人类指令、按照要求回答问题”的助手模型。

```
- **Llama 3 8B**（基础版 / Base） → 只是一个“会猜下一个词”的预训练大模型（pretrained），它很聪明，但不会乖乖听你的指令。 你问它“写一首诗”，它可能继续背唐诗，而不是按你说的写；问它“拒绝回答这个问题”，它可能还是会答。
- **Llama 3 8B Instruct**（指令微调版） → 在基础模型上额外做了 **SFT（Supervised Fine-Tuning） + 可能还有 RLHF/DPO** 等后训练， 让它学会了：
    - 理解人类的各种指令（“帮我写”“解释”“翻译”“拒绝”“角色扮演”……）
    - 按照指令格式化回答（清晰、有帮助、不啰嗦）
    - 学会安全对齐（拒绝有害请求、避免幻觉等）
```

在基础模型的基础上，额外做了指令微调（SFT） + 人类偏好对齐（RLHF / DPO 等）。

```
- 训练数据：成千上万条**高质量的指令-回答对**（例如：“请帮我写一首关于猫的诗” → 完整、原创的诗）。
- 结果：模型学会了：
    - 理解人类指令
    - 按照要求回答（清晰、有帮助、不啰嗦）
    - 拒绝有害请求
    - 角色扮演、格式化输出（Markdown、JSON等）
    - 更安全、更友好
```

|维度|基础模型（Base）|指令微调版（Instruct/Chat）|
|---|---|---|
|是否经过指令微调|**否**|**是**|
|训练数据|海量无标注文本|指令-回答对 + 人类偏好数据|
|典型用途|继续预训练、蒸馏、研究、自己微调|直接聊天、写代码、客服、产品集成|
|听指令能力|很差（基本不听）|很好（乖乖按要求回答）|
|安全性/对齐|几乎没有（容易生成有害内容）|经过对齐（拒绝有害、减少幻觉）|
|输出风格|随意、续写、可能乱七八糟|结构化、友好、有帮助|
|代表模型例子|Llama 3 8B Base Qwen2.5-7B Gemma 2 9B|Llama 3 8B Instruct Qwen2.5-7B-Instruct Grok（默认）|

### 微调

| 类型                       | 中文全称                                   | 具体做什么                  | 数据类型             | 典型代表                                 | 是否属于“指令微调”？    |
| ------------------------ | -------------------------------------- | ---------------------- | ---------------- | ------------------------------------ | -------------- |
| **指令微调**                 | Instruction Tuning / SFT               | 让模型学会听人类指令、按要求回答问题     | ==高质量的“指令-回答”对== | Llama 3 8B Instruct、Qwen2.5-Instruct | **是**（最常见的一种）  |
| **领域微调**                 | Domain-specific Fine-tuning            | 让模型专精某个专业领域（医学、法律、代码等） | ==领域特定文本/问答==    | Med-PaLM、CodeLlama                   | 不是（但可能结合指令微调）  |
| **任务微调**                 | Task-specific Fine-tuning              | 针对单个具体任务优化（如翻译、分类、摘要）  | 任务专用标注数据         | 早期 BERT fine-tune on GLUE            | 不是             |
| **偏好对齐微调**               | Preference Alignment (RLHF/DPO/ORPO)   | 让模型回答更安全、更有帮助、更符合人类偏好  | 人类偏好数据（好坏对比）     | ChatGPT、Claude、Grok                  | 通常是**指令微调的后续** |
| **继续预训练**                | Continued Pretraining                  | 用更多无标注文本继续下一个词预测       | 海量无标注领域文本        | Llama 3 的中文继续预训练                     | 不是             |
| **LoRA / QLoRA 等参数高效微调** | PEFT (Parameter-Efficient Fine-Tuning) | 只微调少量参数（Adapter），节省算力  | ==任何上述数据==       | 几乎所有现代微调都用这个                         | 可以是任何类型        |
**很多人说“微调”时，默认指“指令微调（SFT）”，因为现在（2026年）绝大多数聊天/助手模型都是在基础模型上做 SFT + RLHF 得到的，所以社区里常把“Instruct 版”直接叫“微调版”。**

### temperature（温度）

决定模型的随机程度，模型生成文本每一步都是在做一件事，下一个字选哪个，但不是唯一答案，而是很多候选词：

```
["是", "一个", "非常", "可能", "也许"...]
```

所以这个采样参数，据定模型从里面怎么选择


### MoE
MoE（**Mixture of Experts，专家混合模型**）
MoE = 很多“专家子模型” + 一个“路由器”按需选择部分专家来计算

传统模型：
输入 → 一个大网络 → 输出
MoE：
输入 → 路由器 → 选几个专家 → 汇总输出

Experts（专家）：本质就是多个 FFN（前馈网络）
Gate（门控 / 路由器）：当前 token → 分配给哪些专家

##### 幻觉产生原因理解 

###### 监督微调出现过肯定的标注
 模型回答我们问题的说平是人工标注员的平均水平
例如询问巴黎最好玩的景点有哪些，会回答一个清单，这种回答清单的方式是模型在模拟监督微调训练的时候 数据集人工标注员回答问题的方式
![[截屏2026-01-10 23.11.13.png|300]]
如上图，在监督微调的时候，回答问题的方式，比较肯定的回答，所以测试的时候，问到模型不知道的人名的时候，模型会模仿这种语气去回答，给出一个肯定的答案，哪怕是虚假的

###### 训练数据的局限性与偏差
模型本质上是统计预测器，它学习模式而非“理解”真相如果数据中某个事实出现频率低或冲突多，模型就可能“猜错”。例如，罕见事件的数据少，模型会用常见模式填充空白。

示例：如果训练数据中“哥伦布发现美洲”的变体多（包括错误日期），模型可能输出“1493 年”而非“1492 年”。

###### 自回归生成机制（Autoregressive Nature）
大多数 LLM（如 Transformer-based）是自回归的：每个 token 基于前文预测下一个。它像“接龙游戏”，一旦早期 token 出错，后续会雪球般放大。

为什么导致幻觉：模型追求“连贯性”而非“准确性”。训练目标是最大化似然（likelihood），所以它倾向生成“听起来对”的内容，即使事实错。缺乏外部验证机制（如实时 fact-check）。

示例：问“法国首都是什么？”，模型正确输出“巴黎”；但如果上下文误导（如“假设法国在亚洲”），它可能顺着生成“东京”。

###### 过拟合与泛化不足

模型在训练时过拟合常见模式，但对边缘案例（稀有知识、复杂推理）泛化差。参数规模大（如 72B）虽提升能力，但也放大噪声学习。
当查询超出分布（Out-of-Distribution, OOD），模型“发明”内容来填补。缺乏“不知道”的自我认知，导致过度自信。

###### 注意力机制与上下文处理
Transformer 的注意力层聚焦相关 token，但长上下文时容易“遗忘”或混淆信息。噪声 token（如 tokenizer 切分错误）也会干扰。注意力分散导致模型“回忆”错位，或忽略关键约束。尤其在多轮对话中，早期信息淡化。

#### 如何缓解幻觉

##### 方式一：针对模型训练不知道的情况下，专门进行训练模型不知道的情况下回答

例如：用模型查询模型知识库，一旦发现模型不知道，用编程的方式增加模型拒绝回答，

```
用户：谁是王佳鑫
模型：十分抱歉，我不知道
```

**编程的方式**：模型正常生成回答之前（或生成过程中），通过代码/程序主动拦截，判断当前问题属于“模型不知道”或“模型不应该回答”的范畴，然后强制让模型输出特定的拒绝回答模板，而不是让模型自己生成

| 方式                                | 实现难度  | 拦截时机  | 核心思路                                              | 是否能完全防止幻觉  | 典型使用场景                  |
| --------------------------------- | ----- | ----- | ------------------------------------------------- | ---------- | ----------------------- |
| 1. Prompt 工程（最常见）                 | ★☆☆☆☆ | 生成前   | 在 system prompt 里反复强调“不知道就说不知道”                   | 较弱，容易被绕    | 普通产品、快速上线               |
| 2. 关键词/正则匹配后处理                    | ★★☆☆☆ | 生成后   | 模型输出后检查是否包含“我不知道”“不清楚”等词，否则打回重来                   | 中等，容易漏     | 中小型应用                   |
| 3. 分类器 + 拒绝分支（主流做法）               | ★★★☆☆ | 生成前/中 | 训练/使用一个小分类模型判断“这个问题我知不知道” → 知道就正常生成，不知道就直接返回拒绝v模板 | 较强         | 大多数商业产品 2024-2025 年主流方案 |
| 4. Retrieval 判断 + 阈值（RAG 加强版）     | ★★★★☆ | 生成前   | 先检索知识库 → 相似度低于阈值 → 直接拒绝                           | 很强（针对私有知识） | 企业知识库、客服机器人             |
| 5. Self-Consistency / 多路采样投票 + 拒绝 | ★★★★☆ | 生成中/后 | 生成多条答案 → 如果答案差异很大/出现矛盾 → 拒绝回答                     | 较强         | 高可靠性场景                  |
| 6. 专门训练一个“知道/不知道”判别头（最硬核）         | ★★★★★ | 生成前   | 在 LLM 上加一个二分类头，专门训练判断“我是否知道这个事实”                  | 最强（理论上）    | 顶级实验室/极高要求场景            |

##### 方式二：使用外部工具，例如：联网搜索

```
人类：谁是王佳鑫

模型：<SEARCH START>谁是王佳鑫<SEARCH END>
根据搜索得知，王佳鑫是
```


模型遍历到搜索标签后之后回去外部搜索，停止tocken生成，查询到问题会按照工作记忆流到方式保存到上下文窗口，之后放到神经网络中，预测tocken回答问题

#### 怎么判断模型什么问题知道什么不知道

参考mata的llama模型，四个步骤
1.生成一些问题：用厉害的模型生成问题
```
指令：根据下面三个段落提出三个具体的事实性问题，除问题以外，还要生成正确答案
```

2.测试模型
针对问题询问模型三次以上

3.判断
三次回答错误，认为模型不知道这个答案
4.教模型说不知道

对于模型不知道的问题，专门构建数据集训练

#### tocken化

由于模型只能处理数字，**Tocken化将文字转成ID**，比如：
- “你” → 1001
- “好” → 1002
- 于是“你好” → [1001, 1002]
tocken化方法：
|方法|代表模型|特点|

- 英文：1 token ≈ 4 个字符
- 中文：1 token ≈ 1.5–2 个字符
空格、标点、换行也会被算作 token

Tokenization（token 化）就是把文本切成模型能“吃”的小块（token），就像把==一篇文章切成单词再编号一样==。这是所有大模型能理解你输入的前提！

### 增量模型，原始模型，恢复（recover）
  1️⃣ 原始模型 (path_raw)

  定义: Meta 公司发布的原始 LLaMA-13B 基础模型

  特点:
  - 这是未经任何任务特定训练的"通用"语言模型
  - 由 Meta 在大规模数据上预训练完成
  - 受 Meta 的许可协议约束，不能随意再分发

  类比: 就像一个刚毕业的大学生，有基础知识但没有专业技能

  ---
  2️⃣ 微调后的模型 (UltraLM)

  定义: 使用 UltraChat 数据集在 LLaMA-13B 上微调后得到的模型

  特点:
  - 在原始 LLaMA 的基础上进行对话任务训练
  - 性能更好，更适合聊天场景
  - 包含了 Meta 的原始权重 + 项目的训练成果

  问题: ⚠️ 直接分发完整模型会违反 Meta 的许可协议！

  类比: 像是大学生毕业后接受了公司培训，成为了专业人才

  ---
  3️⃣ 增量模型/权重差异 (path_diff)

  定义: 微调后的模型权重 减去 原始模型权重得到的差异值

  数学原理:
  增量权重 = 微调后的权重 - 原始权重

  内容:
  - 只包含训练过程中改变的部分
  - 不包含 Meta 的原始权重
  - 这是项目独有的训练成果

  为什么这样做:
  - ✅ 绕开版权问题：不直接分发 Meta 的权重
  - ✅ 合法分享：只分享项目自己的贡献
  - ✅ 文件更小：相比完整模型，差异文件理论上可以更小

  类比: 只记录"培训教会了什么新技能"，而不是"整个人的全部知识"

  ---
  4️⃣ 恢复 (recover)

  定义: 将原始模型权重 加上 增量权重，重建完整的微调模型

  数学原理:
  **恢复的模型 = 原始权重 + 增量权重
              = 原始权重 + (微调权重 - 原始权重)
              = 微调权重**

  过程:
  1. 你自己下载原始 LLaMA-13B（从 Meta 获得授权）
  2. 下载 UltraLM 的增量权重（开源项目提供）
  3. 运行恢复脚本，将两者相加
  4. 得到可以使用的完整 UltraLM 模型

  类比: 你找到那个大学毕业生 + 应用公司的培训材料 = 得到专业人才

### 对大模型推理（inference）的理解，即tocken预测

![[截屏2026-01-11 14.16.02.png]]

如果大模型使用搜索引擎，那么会搜索到未知内容，找得到，如果不使用搜索引擎，那么大模型找不到


### 上下文窗口

模型一次性能“同时看到”和“记住”的最大文字量，
上下文窗口 = 模型在一次前向传播中能同时处理的 token 数量上限

### 工作记忆与模糊记忆

**工作记忆=人类短期记忆

文今天中午吃的什么，可以记得，但是文去年中午吃的什么，不记得

**模型模糊记忆=人类长期记忆

人类幼儿园学到1+1=2，一直长久记者，例如询问模型

你可以给出西游记第一章的内容吗，模型会大概输出这部分内容，模型与训练的时候就记着。

如果将西游记第一章内容放到提示词内，模型直接阅读，就是短期工作记忆




### 模型不擅长什么

##### 模型没有自我认知

问模型谁创造的你，没有训练的模型不记着

如果专门训练过，模型会回答正确，但是这还是模型根据提前预设的内容回答，模型无法有自我认知

##### 不擅长求解数学题
![[截屏2026-01-11 15.01.24.png|300]]
右边的是利于模型tocken计算的，他会将问题拆解成一个一个小问题去回答，如果一次性回答，会造成tocken在神经网络堆积，会出错。第一个先给出答案，对模型计算是不利的。

让模型根据记忆去计算得出答案，不如使用代码去计算，因为代码计算是准确的


##### 不擅长数数
![[截屏2026-01-11 15.04.31.png|300]]
模型会把这几个点缩短成tocken，会计算不正确
![[截屏2026-01-11 15.08.42.png|300]]
如果用代码计算，会计算的很准

##### 不擅长拼写

无法像人一样去理解字符串

例如询问：Ubiquitous，针对这个字符串，每隔三个字符串打印出来

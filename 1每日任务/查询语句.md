
### 原始查询语句
查询1：筛选 App 并获取 appIds

```
`db.app.find(
    {
        "mergeStatus": { "$ne": "original" },
        // matchFilters 条件...
    },
    { "appId": 1 }
).skip(0).limit(5000).count()  // 先 count

db.app.find(...).skip(0).limit(5000)  // 再分批获取
db.app.find(...).skip(5000).limit(5000)  // 可能多次`
```

查询2：扩展 mergeId

```
db.app.find(
    { "mergeId": { "$in": appIds } },
    { "appId": 1 }
)
```

查询3：统计 API 总数

```
db.api.countDocuments({
    "appId": { "$in": appIds }
})
```

查询4：统计待分类 API 数量（$or 查询，慢）

```
db.api.countDocuments({
    "$or": [
        { "categoryInfo.templateId": { "$nin": templateIds } },
        { "confirmStatusInfo.confirmStatus": { "$in": confirmStatusList } }
    ],
    "appId": { "$in": appIds }
})
```


### 新的查询语句

查询1：获取 appIds（步骤1）

```
db.app.find(
    {
        "mergeStatus": { "$ne": "original" },
        // matchFilters 动态条件，例如：
        "name": { "$regex": "xxx", "$options": "i" },
        "level": { "$in": ["important", "central"] },
        "appId": { "$nin": ["排除的appId1", "排除的appId2"] }
    },
    { "appId": 1 }
)
```

查询2：扩展 mergeId（步骤2）

```
db.app.find(
    { "mergeId": { "$in": ["app1", "app2", "app3", ...] } },
    { "appId": 1 }
)
```

查询3：统计 API 总数（步骤3，并行）

```
db.api.countDocuments({
    "appId": { "$in": ["app1", "app2", "app3", ... ] }  // 8348个appId
})
```

查询4：统计不需要推理的 API 数量（步骤4，并行，$and 优化）

```
db.api.countDocuments({
    "appId": { "$in": ["app1", "app2", "app3", ... ] },     // 8348个appId
    "categoryInfo.templateId": { "$in": [1, 2, 3] },      // 已关联选择的模板
    "confirmStatusInfo.confirmStatus": { "$nin": ["unconfirmed", "pending"] }  // 不在待确认状态
})
```

### 优化部分

1. 减少 HTTP 调用：原来 Apollo 调用 dataassetserver 2 次，现在减少为 1 次
2. 并行执行：原来查询3和查询4串行执行，现在查询3和查询4并行执行
3. 查询逻辑优化：将查询4从原来的 $or 查询改写为 $and 优化查询

### Mongo不支持链表查询原因
```
  分析结果：mongo 命名空间不支持联表查询的原因

  1. 环境配置

  - MongoDB 版本：4.4.13
  - 部署架构：分片集群 (Sharded Cluster)
    - mongos 路由器：2 个副本
    - configsvr 配置服务器：3 个副本
    - shard0-data 数据分片：2 个副本

  2. 关键发现

  查看分片状态显示：
  dsp.api
      shard key: { "apiId" : "hashed" }  # 使用 apiId 哈希分片

  dsp.app
      shard key: { "appId" : "hashed" }  # 使用 appId 哈希分片

  3. 根本原因

  当我尝试执行联表查询时，得到了明确的错误：

  Error: command failed: {
      "ok" : 0,
      "errmsg" : "dsp.app cannot be sharded",
      "code" : 28769,
      "codeName" : "Location28769"
  }

  错误码 28769 的含义：这是 MongoDB 分片集群的设计限制

  4. 技术原因详解

  MongoDB 4.4 中 $lookup 在分片集群的限制：

  5. 分片集合限制：
    - 当使用 $lookup 时，如果 from 集合（被查找的集合）是分片集合，MongoDB 会拒绝执行
    - dsp.api 和 dsp.app 都是分片集合，因此无法进行联表查询
  6. 为什么有这个限制：
    - 数据分布问题：分片集合的数据分散在不同的分片上
    - 性能问题：跨分片的 JOIN 操作需要在 mongos 层汇总所有分片的数据，会导致严重的性能问题
    - 网络开销：需要从多个分片拉取数据并在 mongos 进行合并
  7. 分片键不匹配：
    - api 表使用 apiId 作为分片键
    - app 表使用 appId 作为分片键
    - 即使放宽限制，使用 appId 进行关联查询时，无法利用分片键优化

  8. MongoDB 版本演进

  - MongoDB 4.4：不支持对分片集合的 $lookup 操作
  - MongoDB 5.0：开始部分支持，但有严格条件
  - MongoDB 5.1+：进一步放宽限制，但仍有性能影响

  6. 当前环境的限制总结

  在你的环境中：
  ✗ api 表（分片集合） ⟷ app 表（分片集合）
    → 不支持 $lookup 联表查询
    → 错误码：28769
    → 这是 MongoDB 4.4 分片集群的设计限制

  这就是为什么在 mongo 命名空间的 pod 中无法执行 api 表和 app 表的联表查询的技术原因。
```

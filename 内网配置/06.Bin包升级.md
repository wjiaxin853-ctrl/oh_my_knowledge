
## **安装前务必阅读如下部分：**

## 1、如果环境全量包部署/升级出现了异常，请先排查和确认清楚问题再继续， 尤其不要在全量包失败后安装增量包。

## 2、apex1.0 安装过程中的前台日志中间会退出在后台运行，如果看到exit0结束， 不代表是安装结束了。 安装过程的监测和安装状态的判断具体看本文档下面的Q&A章节。

## 3、 不要修改你的宿主机的 ssh配置的key， 这会导致部署失败。

### 单机和多节点安装重要区别

多节点安装和升级必须在harbor节点上完成，如何定位harbor节点

kubectl -n harbor get ep

输出的IP地址为harbor节点的数据口地址。

比如一个三节点环境，登录任意一个节点后台，找到harbor所在的节点，需要在这个节点上执行安装。

单节点忽略以上过程

### 全新部署安装

开维护模式

python3 /opt/xdr/apps/dmoc/pylib/dmoc_call.py 'dmoc_ctl.mgr_mode_open' | jq .

安装

bash -x /opt/xdr/upgrade/persist/tools/upgrade.sh {包名} deploy

如果出现安装失败退出了， 可以再解决完问题后用如下命令继续,  请注意，这里说的是安装失败后定位并解决了问题后继续； 如果是啥都不管就直接重搞，**可以看看Q&A章节**

upctl upgrade -s deploy

### 升级安装

开维护模式

python3 /opt/xdr/apps/dmoc/pylib/dmoc_call.py 'dmoc_ctl.mgr_mode_open' | jq .

安装

bash -x /opt/xdr/upgrade/persist/tools/upgrade.sh {包名} upgrade

如果出现安装失败退出了， 可以再解决完问题后用如下命令继续， 请注意，这里说的是安装失败后定位并解决了问题后继续； 如果是啥都不管就直接重搞，**可以看看Q&A章节**

upctl upgrade

### Q&A

注： apex1.0 安装过程中的前台日志中间会退出在后台运行，可以使用 tail -f /data/log/today/upgrade.log 查看。

查看安装进度的2方式：

1、 使用 upctl命令， 或者 /data/bigdata/opt/xdr/upgrade/unzip/upctl， 在安装的最初阶段是没有upctl命令的，要等解包完了才有。

upctl status

upctl status -m ｛接模块名｝

upctl status -m  {继续接子模块名}

upclt log -m {接模块名}
![[Pasted image 20251229103306.png]]

2、查看实时日志

tail -f /data/log/today/upgrade.log

3、 如何判断安装已经结束了，可以用如下标志：

- upctl status  
  所有阶段为绿色表示安装完成，如果有红色表示安装失败退出。

4、 一些骚操作后的解决办法：

比如你在安装过程中，强制退出了安装， 或者做了关机重启之类，此时又想重新开始：

postgresql.sh pgsql 进入数据库， delete from tasks; 把历史任务清一下，再从头开始。

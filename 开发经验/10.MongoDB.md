### DSP的Mongo部署
- MongoDB 版本：4.4.13

部署类型： MongoDB Sharded Cluster（分片集群）

  - 部署架构：分片集群 (Sharded Cluster)
    - mongos 路由器：2 个副本
    - configsvr 配置服务器：3 个副本
    - shard0-data 数据分片：2 个副本


服务信息：
  - 主服务名称：mongo-mongodb-sharded
  - 服务类型：ClusterIP
  - 集群 IP：172.18.137.115
  - 端口：27017/TCP
  - 目标端口：mongodb/TCP

  连接方式：
  在集群内部可以通过以下方式连接：
  - 服务名称：mongo-mongodb-sharded.mongo.svc.cluster.local:27017
  - 或简写：mongo-mongodb-sharded:27017（在同一命名空间内）

### 常见概念词

##### **集合（Collection）**：
传统关系型数据库里的 “表”（Table），但 MongoDB 是文档型数据库，所以集合里存的不是“行”，而是 一堆 JSON/BSON 格式的文档（Document）
```
集合 users（用户表）
├── { _id: 1, name: "张三", age: 28, city: "北京" }
├── { _id: 2, name: "李四", age: 35, city: "上海" }
└── { _id: 3, name: "王五", age: 22, city: "广州" }
```
集合是 逻辑概念，没有固定 schema（结构），文档可以字段不同，所以我们可以定义mongo的schema
##### Shard（分片节点）

- Shard = **“数据存储分片”** 或叫 **“分片服务器”**
- 简单说：**一台（或一组）物理/虚拟服务器**，负责存储整个集合的一部分数据
```
例子：假设有 10 亿条用户数据

- 单台服务器存不下 → 把数据切成 3 份
- Shard0 存前 3 亿条
- Shard1 存中间 3 亿条
- Shard2 存后 4 亿条

```

##### 分片（Sharding）
- 分片 = 把一个大集合的数据 水平切分（horizontal partitioning）后，分散存储到多个 Shard 上的过程
- 目的：解决单机容量、IO、CPU 瓶颈，实现 水平扩展（加机器就能扩容）
```
客户端 ──► mongos（路由器，多个可负载均衡）
           │
           ├─► config servers（配置服务器，3节点副本集，存元数据）
           │
           ├─► Shard 0（副本集）  ← 存一部分数据
           ├─► Shard 1（副本集）  ← 存另一部分数据
           └─► Shard 2（副本集）  ← 存剩余数据
```

mongos 知道每条数据应该去哪个 Shard（靠 config servers 里的元数据）

shard Key（分片键）  = 用来决定“哪条文档放到哪个 Shard”的字段

单机（无分片）                  分片集群（有分片）
```
┌────────────────┐             ┌───────────────────────┐
│ 集合 users      │             │ mongos                │
│ 10亿条数据      │   ──►       │ （路由）               │
│ 全在一台机器    │             └───────────────────────┘
└────────────────┘                        │
                                          ▼
                           ┌───────┐   ┌───────┐   ┌───────┐
                           │ Shard0│   │ Shard1│   │ Shard2│
                           │ 3亿条 │   │ 3亿条 │   │ 4亿条 │
                           └───────┘   └───────┘   └───────┘
```


- **集合** = 表（存一堆文档）
- **Shard** = 存数据的“分片服务器”（一台或一组）
- **分片（Sharding）** = 把大集合切碎，分散存到多个 Shard
- **分片键（Shard Key）** = “切蛋糕的刀”，决定怎么切、切哪里


### 查询语句

#### $in
「查询 / 筛选条件运算符」用于从已有集合中**匹配符合条件的文档**，类似 SQL 中的 `IN` 关键字

“在指定的数组范围内匹配字段值”—— 只要目标字段的值是数组中的任意一个，就会被筛选出来

#### $lookup
穿链表查询（联表查询）：“把两条链（两个集合）穿起来查”
本质上指的就是 MongoDB 的 聚合管道（aggregation pipeline） 中使用 $lookup 阶段实现的 类似 SQL LEFT JOIN / INNER JOIN 的跨集合查询。
```
集合 orders（订单）               集合 users（用户）
┌──────────────┐                 ┌──────────────┐
│ _id          │                 │ _id          │
│ orderNo      │                 │ name         │
│ amount       │                 │ age          │
│ userId  ←────┼───────┐         └──────────────┘
└──────────────┘       │                   ↑
                       └───────────────┐   foreignField
                                      │
                                      └─ localField
```

用 $lookup 就是在 orders 文档里“穿”进去一个 users 数组（或单个对象），就像把两条链用一个环扣在一起。

### 对象（object）与数组（Array）区别
##### **对象**
文档、哈希、字典、JSON 对象，**花括号 `{ }，键值对（Key-Value）`**
```
{
  "name": "张三",
  "age": 28,
  "city": "北京"
}
```

##### 数组
列表、集合，**方括号 `[ ]`** 有序的值列表（Value List）
```
["北京", "上海", "广州", "深圳"]
```

### 导出mongo数据

将mongo表的指定表数据导出

```
MONGO_HOST=$(kubectl -n mongo get svc mongo-mongodb-sharded -o jsonpath='{.spec.clusterIP}') && MONGO_PASSWD=$(kubectl -n mongo get secrets root -o jsonpath='{.data.root}' | base64 -d) && mongoexport --host="$MONGO_HOST" --port=27017 --username=root --password="$MONGO_PASSWD" --authenticationDatabase=admin --db=dsp --collection=file_inference --type=csv --fields=parseInfo,addTime,md5 --out=/root/dsp/fileparser/file_inference.csv
```

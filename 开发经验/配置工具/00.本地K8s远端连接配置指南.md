
## 前置需求

- 已安装 kubectl 工具
- 获取了远端 K8s 集群的 kubeconfig 文件
- 能够访问远端服务器（网络连通）

## 正常配置流程

### 第一步：获取 kubeconfig 文件（远端集群环境）

从远端 K8s 集群管理员处获取 kubeconfig 文件，通常位置是：

```bash
cat ~/.kube/config
```

kubeconfig 文件包含的关键信息：
- **clusters**: 集群服务地址和证书信息
- **contexts**: 上下文配置（关联集群和用户）
- **users**: 用户认证信息（证书或 token）
- **current-context**: 当前使用的上下文

会获得如下信息：
![[截屏2026-01-28 10.26.47.png]]

### 第二步：确认连接信息

查看 kubeconfig 中的连接信息：

```bash
kubectl config view
```

检查以下内容：
- `server`: API 服务器地址
- `certificate-authority-data` 或 `insecure-skip-tls-verify`: 证书配置
- `client-certificate-data` 和 `client-key-data`: 客户端证书

### 第三步：验证网络连接

#### 测试 DNS 解析（如果使用域名）
```bash
# 如果server地址是域名
ping <domain-name>
nslookup <domain-name>
```

#### 测试端口连通性
```bash
# 测试 K8s API 端口（默认6443）
nc -zv <server-ip> 6443 -w 3
# 或使用 telnet
telnet <server-ip> 6443
```

### 第四步：测试连接

#### 简单测试
```bash
kubectl cluster-info
```

#### 获取资源列表
```bash
kubectl get pods -A
```

#### 详细调试
```bash
kubectl get pods -A -v=8
```

### 第五步：配置调整

根据实际情况调整 kubeconfig：

**情况1：使用域名无法解析**
- 改为使用 IP 地址
- 或在本地 `/etc/hosts` 添加 DNS 映射

**情况2：证书验证失败**
- 移除 `certificate-authority-data`
- 添加 `insecure-skip-tls-verify: true`（仅用于开发/测试环境）

**情况3：同时使用两种配置冲突**
- 不能同时指定 `certificate-authority-data` 和 `insecure-skip-tls-verify`
- 二选一配置

## 问题排查与解决方案

### Q1: DNS 无法解析域名错误

**错误表现：**
```
E0128 10:05:12.721549 10523 memcache.go:265] "Unhandled Error" err="couldn't get current server API group list: Get \"https://k8s.server.sr:6443/api?timeout=32s\": dial tcp: lookup k8s.server.sr: no such host"
```

**原因分析：**
- 本地 DNS 无法解析 kubeconfig 中的域名
- 可能因为跨网络环境、DNS 配置不一致或域名只在内网有效

**解决方案：**

**方案A：改用 IP 地址（推荐）**
```bash
# 编辑 ~/.kube/config
# 将
server: https://k8s.server.sr:6443
# 改为
server: https://10.65.245.95:6443
```

**方案B：添加本地 DNS 映射**
```bash
# 编辑 /etc/hosts (macOS/Linux)
# 添加一行
10.65.245.95  k8s.server.sr
```

### Q2: 连接超时（i/o timeout）

**错误表现：**
```
E0128 10:11:29.007487 12510 memcache.go:265] "Unhandled Error" err="couldn't get current server API group list: Get \"https://10.65.245.95:6443/api?timeout=32s\": dial tcp 10.65.245.95:6443: i/o timeout"
```

**原因分析：**
- 网络连接不通
- 防火墙阻止连接
- K8s API 端口未开放
- 需要通过 VPN 或跳板机

**解决方案：**

**第一步：检查网络连通性**
```bash
# 测试是否能 ping 通服务器
ping -c 4 10.65.245.95
```

**第二步：检查具体端口是否开放**
```bash
# 使用 nc (netcat) 测试
nc -zv 10.65.245.95 6443 -w 3

# 或使用 telnet
telnet 10.65.245.95 6443
```

**第三步：排查网络问题**
- 如果 ping 通但端口不通，也就是k8s没有开放端口，需要执行

```
kubectl edit globalnetworkpolicies allow-external-ingress
```

### Q3: TLS 证书验证失败

**错误表现：**
```
error: specifying a root certificates file with the insecure flag is not allowed
```

**原因分析：**
- 同时配置了 `certificate-authority-data` 和 `insecure-skip-tls-verify`
- Kubernetes 不允许这两个配置同时存在

**解决方案：**

**移除证书配置，仅使用 insecure 标志**

编辑 `~/.kube/config`，修改 clusters 部分：

```yaml
# 修改前
clusters:
- cluster:
    certificate-authority-data: LS0tLS1CRUdJTi...  # 删除此行
    insecure-skip-tls-verify: true
    server: https://10.65.245.95:6443
  name: kubernetes

# 修改后
clusters:
- cluster:
    insecure-skip-tls-verify: true
    server: https://10.65.245.95:6443
  name: kubernetes
```

**或使用命令行方式：**
```bash
# 设置 insecure-skip-tls-verify
kubectl config set-cluster kubernetes --insecure-skip-tls-verify=true

# 移除 certificate-authority
kubectl config unset clusters.kubernetes.certificate-authority
```

### Q4: 认证失败（403 Forbidden）

**错误表现：**
```json
{
  "status": "Failure",
  "message": "namespaces is forbidden: User \"system:anonymous\" cannot list resource \"namespaces\""
}
```

**原因分析：**
- kubeconfig 中的认证信息未被识别
- 使用了匿名用户访问

**解决方案：**

**检查 kubeconfig 中的用户配置：**
```bash
kubectl config view
# 确认 users 部分的 client-certificate-data 和 client-key-data 存在
```

**验证当前使用的上下文：**
```bash
kubectl config current-context
kubectl config get-contexts
```

**切换到正确的上下文：**
```bash
kubectl config use-context kubernetes-admin@kubernetes
```

---

### Q5: 无法使用 TLS 证书的正确配置

**场景：** 想要使用完整的 TLS 证书验证而不是跳过验证

**解决方案：**

1. **确保 certificate-authority-data 正确**
   ```bash
   # 提取证书数据
   echo "LS0tLS1CRUdJTi..." | base64 -d > ca.crt
   ```

2. **使用完整的证书配置**
   ```yaml
   clusters:
   - cluster:
       certificate-authority-data: LS0tLS1CRUdJTi...  # 保留此行
       server: https://10.65.245.95:6443
     name: kubernetes
   ```

3. **不添加 insecure-skip-tls-verify 标志**

4. **测试连接**
   ```bash
   kubectl cluster-info
   ```

## 完整配置示例

### 最小化配置（开发环境）

```yaml
apiVersion: v1
kind: Config
clusters:
- cluster:
    insecure-skip-tls-verify: true
    server: https://10.65.245.95:6443
  name: kubernetes
contexts:
- context:
    cluster: kubernetes
    user: kubernetes-admin
  name: kubernetes-admin@kubernetes
current-context: kubernetes-admin@kubernetes
users:
- name: kubernetes-admin
  user:
    client-certificate-data: LS0tLS1CRUdJTi...
    client-key-data: LS0tLS1CRUdJTi...
```

### 完整配置（生产环境）

```yaml
apiVersion: v1
kind: Config
clusters:
- cluster:
    certificate-authority-data: LS0tLS1CRUdJTi...
    server: https://k8s.example.com:6443
  name: kubernetes
contexts:
- context:
    cluster: kubernetes
    user: kubernetes-admin
  name: kubernetes-admin@kubernetes
current-context: kubernetes-admin@kubernetes
users:
- name: kubernetes-admin
  user:
    client-certificate-data: LS0tLS1CRUdJTi...
    client-key-data: LS0tLS1CRUdJTi...
```

## 常用命令参考

```bash
# 查看当前配置
kubectl config view

# 查看可用的上下文
kubectl config get-contexts

# 切换上下文
kubectl config use-context <context-name>

# 临时跳过 TLS 验证
kubectl cluster-info --insecure-skip-tls-verify

# 详细调试信息
kubectl get pods -A -v=8

# 直接用 curl 测试（需要证书）
curl -k https://10.65.245.95:6443/api/v1/namespaces
```

Prometheus 是一个监控平台，它通过抓取目标上的 HTTP 指标端点来收集被监控目标的指标
## 原理图

![[Pasted image 20251211193130.png|600]]

### 1. 核心组件：Prometheus Server

它是整个系统的 “大脑”，包含 3 个子模块：

- **Retrieval**：主动拉取（Pull）监控指标（从 Exporters、Pushgateway 等）。
- **TSDB**：将指标以 “时间序列数据” 形式存储在本地磁盘（HDD/SSD）。
- **PromQL 接口**：提供查询语言，支持指标的筛选、聚合、计算。

### 2. 数据采集相关

- **Jobs/Exporters**：
    
    非原生支持的系统（如服务器、MySQL、Redis），通过 Exporters（如 Node Exporter）暴露`/metrics`接口，供 Prometheus 拉取指标。
- **Short-lived jobs（短任务）**：
    
    生命周期短的任务（如 CI/CD 任务），无法被主动拉取，需先将指标**推送到 Pushgateway**，再由 Prometheus 从 Pushgateway 拉取。

### 3. 服务发现：Service Discovery

适配云原生环境（如 Kubernetes）的动态性，自动发现新的监控目标（如新增的 Pod），避免手动配置。

### 4. 告警流程：Alertmanager

- 接收 Prometheus Server 触发的告警规则。
- 对告警进行**去重、分组、路由**，最终通过 PagerDuty 等渠道通知用户。

### 5. 可视化与扩展

- **Grafana**：对接 Prometheus 数据源，将指标可视化（生成仪表盘、图表）。
- **API clients**：支持自定义程序通过 API 查询指标。

### 核心流程总结

1. Exporters/Pushgateway 提供指标 → 2. Prometheus 拉取并存储 → 3. 用 PromQL 查询 / 配置告警 → 4. Alertmanager 处理告警并通知 → 5. Grafana 可视化展示。

## Promethus的配置

Prometheus 的配置文件是yaml格式，即`prometheus.yml`

## Promethus的本地DSP部署

dsp采用了VictoriaMetrics作为Prometheus Server的代替档案，完全兼容Promethus的协议

## Promethus标签说明

 - Prometheus/VictoriaMetrics 在抓取指标时，如果标签名与内置标签冲突，会自动添加 exported_  前缀
 - 因此实际查询时：
   - endpoint → exported_endpoint
   - method → exported_method（或 method，需要在 Grafana 中测试确认）
   - status → status

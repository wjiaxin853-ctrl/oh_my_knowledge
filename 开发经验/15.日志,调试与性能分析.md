# 日志级别

| 级别（英文）         | 级别（中文）  | 数值（常见） | 含义与使用场景                            | 生产环境是否开启 |
| -------------- | ------- | ------ | ---------------------------------- | -------- |
| FATAL / ERROR  | 致命 / 错误 | 最高     | 系统发生严重错误，可能导致崩溃、数据丢失、服务不可用，必须立即处理  | 必须开启     |
| ERROR          | 错误      | 高      | 业务逻辑出错、异常、请求失败等，但系统还能继续运行          | 必须开启     |
| WARN / WARNING | 警告      | 中高     | 可预见的潜在问题、配置不当、性能瓶颈、即将出错但暂时还能用的情况   | 建议开启     |
| INFO           | 信息      | 中      | 重要业务流程的进展、系统启动/关闭、关键操作记录、正常业务日志    | 生产通常开启   |
| DEBUG          | 调试      | 低      | 开发调试用的详细信息、变量值、方法进入/退出、详细执行路径      | 生产通常关闭   |
| TRACE          | 跟踪 / 追踪 | 最低     | 极其详细的跟踪信息（如每个 SQL、每个请求的完整上下文、方法参数） | 生产几乎关闭   |

排序规律（严重程度从高到低）： FATAL > ERROR > WARN > INFO > DEBUG > TRACE

==大多数UNIX系统，将日志文件放到：**/var/log文件夹**==

##### 设置断点
断点会让程序运行到断点后立刻停止
```
print("1")  
  
print("2")  
  
print("3")
```

正常输出是1，2，3
增加断点后，输出

```
print("1")  
  
breakpoint()  //增加断点
print("2")  
  
print("3")
```

### Fetch

**git fetch**：只下载、不动本地代码，只把远程仓库的最新提交、分支指针等下载到本地（更新 .git 里的远程跟踪分支），不碰你的工作目录和当前分支。你可以用它来“先看看别人改了什么，再决定要不要合”。（下载）

**git pull**：下载 + 自动合并，相当于 git fetch + git merge（或 git rebase，取决于配置）。它先下载更新，然后自动合并到你当前所在的分支，直接改动你的工作目录。（下载+安装）

**正确用法**：
```
git fetch origin
```
远程的最新 commit 被下载到本地，但你当前文件不变。

安全查看差异：

```
git log origin/main..main          # 看远程比本地多了什么
git diff origin/main main          # 看代码差异
git log --graph --oneline --all    # 看完整历史图
```

满意了手动合并

```
git merge origin/main              # 或 git rebase origin/main
```

### HEAD

HEAD 就是 Git 用来标记“你现在站在哪个 commit 上”的指针，正常情况（最常见，占 99%）：HEAD 指向当前分支的最新 commit。

### 冲突解决

##### 解决思路
从主分支获得代码开发后，其他人也进行开发并合并到主分支，导致当前分支合并主分支落后提交，所以需要将当前主分支代码拉去，并将本地修改提交更新到主分支最新的之上，最后提交合并请求

先提交本地未提交的修改（如果有）
```
git add .
git commit -m "你的提交信息"
```

拉取最新主分支

```
git fetch origin
```

变基到主分支

```
git rebase origin/develop-DSP3.0.33
```

如果遇到冲突，解决后执行

```
git add .
git rebase --continue
```

确认只有你的提交

```
git log --oneline origin/develop-DSP3.0.33..HEAD
```

强制推送到远端

```
git push origin <你的分支名> --force-with-lease
```

## 本地分支已修改，想同步远端主分支代码，并保留修改（落后提交）


##### 1.先获取远端最新代码（在本地个人分支）

```
git fetch origin develop-DSP3.0.35
```

##### 2.将主分支的最新代码合并到当前分支

```
git merge origin/develop-DSP3.0.35
```

  或者使用 rebase（保持提交历史线性）：

```
git fetch origin develop-DSP3.0.33
git rebase origin/develop-DSP3.0.33
```

> [!注意]
> 如果进入一个编辑界面，选择insert模式之后点击esc之后:wq

##### 3.如果有冲突，解决冲突后：

merge 方式
```
git add .
git commit
```

rebase 方式
  
```
git add .
git rebase --continue
```

也就是gitcommit一下即可，之后pycharm的会自动消失
##### 4.强制推送到远端(因为rebase改变了提交历史)

注意修改分支名称

```
git push --force-with-lease origin feature-DSP3.0.33-waterroad
```

# 挂载理解

 `volumeMounts`：这个是容器视角的挂载

`volumes`：这个是pod视角的挂载，也就是相对于宿主机器，也就是节点

比如：
pod容器内挂载配置
```
volumeMounts:
  - name: workdir          # 关键：引用名为 workdir 的 volume
    mountPath: /tmp        # 挂载到容器内的 /tmp 目录
```
pod对节点的挂载配置
```
volumes:
  - name: workdir          # 关键：定义名为 workdir 的 volume
    emptyDir:
      sizeLimit: 2Gi       # 限制该目录最大 2GiB
```

也就是讲这个pod容器的这个/tmp目录挂载到宿主机器的这：/var/lib/kubelet/pods/（pod-uid）/volumes/的这个目录，这是k8s默认的，

![[Pasted image 20260912154938.png|300]]

但是如果想制定到节点一个目录，增加参数：mountPath
即
```
volumes:
  - name: workdir          # 关键：定义名为 workdir 的 volume
    hostPath:
        path: /tmp                   # 节点上的 /tmp
        type: Directory              # 必须是已存在的目录
```
此时必须删除emptyDir，因为这个挂载方式就是k8s托管的，就是指的是/var/lib/kubelet/pods/...
就是去了限制2Gb的功能

```
kubectl get svc -n dsp |grep apo
```

输出：
```
dsp-apollo-api   ClusterIP   172.18.31.8    <none>   8080/TCP    30m
```

```
curl http://172.18.31.8:8080/metrics | grep apollo_api_latency_seconds
```

构造请求（直接宿主机器执行）：

```
for i in {1..24}; do
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] 请求 #$i:"
    curl -s -w "  状态码: %{http_code} | 响应时间: %{time_total}s\n" http://10.65.245.95:8080/healthy
    sleep 1
done
```

解释：
```
• 原理链路（结合你的配置）：

  - 应用：apolloserver 中间件把接口时延等指标写入 /metrics，监听在 Pod 的 8080 端口（端口名 metrics）。
  - 抓取：Helm 新增的 VMPodScrape（apolloserver/scripts/chart/templates/vm-scrape.yaml，vmScrape: true）按 Pod 标签 app=dsp-apollo-api 抓取 PodIP:8080/metrics，数据写入
    VictoriaMetrics（或 Prometheus）。
  - 展示：Grafana 的数据源指向这个 VictoriaMetrics/Prometheus，面板查询 apollo_api_latency_seconds_*。只有在最近有接口请求时，rate(...[5m])/histogram_quantile 才有曲线。

  为什么节点 IP:8080 不通

  - Pod 未开 hostNetwork，Service 是 ClusterIP。节点 IP 上没有 8080 监听，所以连接拒绝。你能用 172.18.31.8:8080（ClusterIP）或 Pod 内 localhost:8080，是因为 kube-proxy
    转发 ClusterIP。

  如何确保数据能到 Grafana

  1. 抓取生效：
      - kubectl get vmpodscrape -n dsp 应看到 *-pod-monitor。
      - kubectl get endpoints -n dsp dsp-apollo-api，确保有 Pod IP，端口 8080。
      - 在 Pod 内 curl -s localhost:8080/metrics | head 确认暴露。
  2. 生成样本：
      - 调用几次 /apollo/internal/... 真实接口，让直方图/计数器有数据。
  3. 数据源正确：
      - Grafana 数据源 UID 要指向当前 VictoriaMetrics/Prometheus（你的 grafana.json 里是 PD1016327C161BF04）。
  4. 面板查询：
      - 关注查询里的时间范围和 rate 窗口（5m），确保有最近请求。
```

# 针对taskdispatch进行配置
### 进入编译容器

```
docker exec - it dsp-dev bash
```

### 进入指定目录

```
cd /root/dsp/taskdispatch
```

### 编译项目

`两个项目会一起编译`

```
make build
```

### 二进制文件输出位置

  - `taskdispatch/INSTALLROOT/usr/local/bin/task_distribute.bin
  - `taskdispatch/INSTALLROOT/usr/local/bin/config_manager.bin

### 放入对应pod位置

##### 方式一：cp命令
```
kubectl cp /root/dsp/taskdispatch/INSTALLROOT/usr/local/bin/config_manager.bin dsp/dspm-taskdispatch-55f6997bcb-pdxjk:/usr/local/bin/config_manager.bin
```

##### 方式二：管道传输

`传输config_manager.bin

```
  kubectl exec -n dsp dspm-taskdispatch-55f6997bcb-pdxjk -c dspm-taskdispatch-config-manager -i -- sh -c 'cat > /usr/local/bin/config_manager.bin && chmod +x /usr/local/bin/config_manager.bin' < /root/dsp/taskdispatch/INSTALLROOT/usr/local/bin/config_manager.bin
```

`传输config_manager.bin

```
  kubectl exec -n dsp dspm-taskdispatch-55f6997bcb-pdxjk -c dspm-taskdispatch-task-distribute -i -- sh -c 'cat > /usr/local/bin/task_distribute.bin && chmod +x /usr/local/bin/task_distribute.bin' < /root/dsp/taskdispatch/INSTALLROOT/usr/local/bin/task_distribute.bin
```
